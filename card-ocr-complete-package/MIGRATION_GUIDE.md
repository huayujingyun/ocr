# 从云端OCR迁移到本地PaddleOCR指南

## 迁移概述

本文档帮助您从云端OCR服务迁移到本地PaddleOCR-VL-1.5，实现完全离线运行。

## 迁移前后对比

| 特性 | 云端OCR (v1.0) | 本地PaddleOCR (v2.0) |
|------|----------------|----------------------|
| 网络依赖 | 需要联网 | 完全离线 |
| 识别速度 | 中等 | 较快 |
| 识别精度 | 较高 | 高 |
| 数据隐私 | 上传到云端 | 完全本地 |
| 部署复杂度 | 简单 | 中等 |
| 运行成本 | 按使用量计费 | 免费 |

## 迁移步骤

### 第1步：备份现有数据（可选）

如果您有重要的识别结果或配置，建议先备份：

```bash
# 备份配置文件
cp .env .env.backup

# 如果有数据库，备份数据
# （根据您的数据库类型执行相应备份命令）
```

### 第2步：更新代码

您已经完成了代码更新，主要包括：

1. ✅ 添加 `backend/` 目录
   - `main.py` - FastAPI后端服务
   - `ocr_service.py` - PaddleOCR服务封装
   - `requirements.txt` - Python依赖
   - `Dockerfile` - Docker镜像配置

2. ✅ 修改 `src/app/api/ocr/route.ts`
   - 从云端SDK调用改为本地API调用
   - 优化批量识别逻辑

3. ✅ 更新 `.coze` 配置
   - 添加Python依赖
   - 更新启动脚本

### 第3步：安装依赖

```bash
# 安装Python依赖
cd backend
pip3 install -r requirements.txt

# 安装Node.js依赖（如果需要重新安装）
cd ..
pnpm install
```

### 第4步：启动服务

```bash
# 方式1：使用coze命令（推荐）
coze dev

# 方式2：手动启动
# 终端1：启动后端
cd backend
python3 main.py

# 终端2：启动前端
cd ..
pnpm run dev
```

### 第5步：验证功能

1. **检查后端健康状态**
   ```bash
   curl http://localhost:8001/health
   ```

   预期输出：
   ```json
   {
     "status": "healthy",
     "ocr_ready": true
   }
   ```

2. **访问前端应用**
   打开浏览器访问：http://localhost:5000

3. **测试OCR识别**
   - 上传一张购物卡图片
   - 框选卡号和密码区域
   - 点击"开始识别"
   - 验证识别结果

## 注意事项

### 1. 首次启动时间

**云端OCR**：即时启动
**本地PaddleOCR**：首次启动需要1-5分钟（下载模型文件）

**解决方案**：
- 首次启动后，模型会缓存到本地
- 后续启动时间约10-30秒

### 2. 资源占用

**云端OCR**：前端占用50-100MB内存
**本地PaddleOCR**：前端50-100MB + 后端500-1000MB

**要求**：
- 系统内存至少4GB
- 磁盘空间至少3GB

### 3. 识别精度差异

**云端OCR**：
- 使用AI视觉模型，擅长结构化数据提取
- 对模糊图片有较好的容错性

**本地PaddleOCR**：
- 专用OCR引擎，文字识别精度更高
- 对清晰度要求较高
- 建议使用模板框选模式以获得最佳效果

### 4. 传统OCR模式限制

**云端OCR**：使用AI模型理解语义，可以智能区分卡号和密码
**本地PaddleOCR**：使用正则表达式提取，可能无法准确区分

**建议**：
- 对于复杂的卡片布局，使用模板框选模式
- 对于简单的卡片布局，传统OCR模式也能正常工作

## 常见问题

### Q1: 迁移后识别结果不同怎么办？

**A**: 这是正常的，因为识别引擎不同。建议：
1. 尝试使用模板框选模式
2. 调整图片预处理方式
3. 提高输入图片质量

### Q2: 能否回退到云端版本？

**A**: 可以。如果您想回退，需要：
1. 恢复旧版本的 `src/app/api/ocr/route.ts`
2. 删除 `backend/` 目录
3. 恢复 `.coze` 配置

### Q3: 生产环境推荐使用哪个版本？

**A**: 取决于您的需求：
- **需要离线运行**：使用本地PaddleOCR
- **数据隐私要求高**：使用本地PaddleOCR
- **追求简单部署**：使用云端OCR
- **高并发场景**：使用云端OCR（或部署多个本地实例）

### Q4: 本地版本是否支持GPU加速？

**A**: 支持。修改 `backend/ocr_service.py`：
```python
self._ocr_engine = PaddleOCR(
    use_gpu=True,  # 启用GPU
    # ...
)
```

### Q5: 能否同时支持云端和本地？

**A**: 可以。修改前端API路由，添加切换逻辑：
```typescript
const useCloudOCR = process.env.USE_CLOUD_OCR === 'true';

if (useCloudOCR) {
    // 使用云端OCR
} else {
    // 使用本地PaddleOCR
}
```
